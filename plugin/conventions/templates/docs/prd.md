## Problem

What is wrong or missing today, and for whom. Be specific about the person and the situation. Cite evidence where there is some, and mark assumptions as assumptions.

## Users

Who uses it, in what situation, and what they are trying to get done. Name the primary user first.

## What we're building

The core idea in a few paragraphs. Describe the mechanism and the experience, not every feature.

## Goals and success criteria

What has to be true for this to count as working. Each criterion should be checkable: a measurement, a task a user can finish, or a question the product answers. Say how each is measured, so an outcome review can check it after a release.
